## 시각 디자인 원칙

- 보라색은 주요 행동·선택·AI 맥락에 사용하고 바탕은 중립색으로 유지.
- 제목·본문·보조 설명의 크기와 굵기를 구분하고, 카드 모서리·간격·테두리를 정렬.
- 숫자는 인맥 수 자랑이 아니라 누르면 바로 처리할 수 있는 업무량을 우선 노출.
- 명함 등록은 업로드 → 정보 확인 → 인맥 연결의 순서를 명시.
- 기존 6개 메뉴와 데이터 저장 계약을 유지. 완료된 업무를 기한 지남으로 분류하지 않음.
- `experience.css`는 통합 제품 경험을 담당하며, 기존 이식 CSS 전체를 이번 작업에서 재작성하지 않음.

## VC 관점의 냉정한 평가

기능 수나 그래프의 시각적 복잡성은 제품 경쟁력을 입증하지 않는다. 외부 사람을 자주 만나는 사용자가 실제로 **찾으려던 사람을 근거와 함께 찾고, 후속 연락을 마치는지**가 검증 대상이다. UI 개선으로 이 루프는 더 잘 드러나지만, 반복 사용·유료 전환·검색 정확도·업무 시간 절감은 이번 점검으로 입증되지 않았다.

다음 사용자 테스트는 팀원 6명에게 동일한 과업을 주고 별도 기록한다.

1. 명함 등록 → 추출값 검토 → 만남 맥락 저장: 완료 시간, 수정 필드 수, 이탈 지점.
2. 며칠 전 만난 인물을 이름 없이 검색: 첫 검색 성공 여부, 재질문 수, 근거 이해 여부.
3. 미완료 약속 찾기 → 인물 확인 → 업무 완료: 완료 시간, 잘못된 대상 선택 여부.
4. 며칠 후 다시 사용하려는 이유: 다음 방문 의도와 실제 재방문은 구분한다.

임의의 성공 수치나 개선율을 만들지 않는다. STT 및 실제 LLM 메일 생성은 후속 개발 항목이다.
