# ADR 0012 — 누적 사용 한도 제거, 단기 대량 호출만 제한

- 날짜: 2026-09-22
- 상태: 사용자 명시 승인으로 구현·보호된 Preview 배포 및 실제 전체 흐름 검증 완료.
- 이전 ADR 0009 및 0011의 앱 일/월 호출 한도 결정을 이 범위에서 대체한다. 제공자 측 설정은 변경하지 않는다.

## 결정

1. Context/Recall/indexing의 일·월 누적 한도와 기존 AI_LIVE_DAILY_CALL_LIMIT / AI_LIVE_MONTHLY_CALL_LIMIT 설정을 제거한다. mock 기본값과 명시적 live 활성화는 유지한다.
2. 기존 DB 호출 예약 테이블과 workspace advisory lock으로 최근 60초간 최대 60회 모델 요청만 허용한다. 61번째는 제공자 호출 전에 AI_RATE_LIMITED로 차단한다. 과거 누적 내역은 비용 추적용으로 보존하며 차단 근거로 쓰지 않는다.
3. 명함 OCR도 기존 일 100/월 1,000 한도를 제거한다. 기존 제공자 범위 lock·호출 이력으로 최근 60초간 20회, 최소 1초 간격만 유지한다. 같은 이미지 동시 처리 및 같은 작업 재전송 방어도 유지한다.
4. 차단 시 429, Retry-After와 한국어 대기 안내를 반환한다. 새로운 자동 재시도는 추가하지 않는다. 작업 도중 단기 제한이 발생한 경우 이미 확정된 원문·기억은 보존되며 검색 준비가 실패할 수 있다.
5. Preview 접근 보호·입력 크기 제한·timeout·서버 전용 키·provider 제한은 유지한다. 설정은 소규모 보호된 MVP의 단기 호출 방어이며 트래픽의 악의성을 판별하거나 분산 서비스 거부 공격 전체를 방어하는 시스템은 아니다.
6. 총 사용자 테스트 횟수는 앱에서 제한하지 않는다. OpenAI/Voyage/Naver의 잔액·요금·속도 제한은 각각 적용된다. 테스트 스크립트의 별도 승인/실행 횟수 제한은 웹앱 사용 한도가 아니다.

## 검증

- 단위·회귀 106개, lint/typecheck/format/build 통과.
- rollback-only PostgreSQL 검증: 누적 1,000건 무시, AI 60/OCR 20 경계 차단, 60초 창 경과 후 회복, OCR 1초 간격·중복 방어 통과. 유료 호출 0회, fixture/DB 부수효과 전부 롤백.
- 분산 부하 시험은 하지 않았다. DB lock 하에서 집계·예약이 이루어지는 기존 분산 제어 구조를 유지했다.
