# 0015 — 기존 프론트와 Canonical 백엔드 결합

- 날짜: 2026-10-08
- 상태: 구현, 최종 검증·Preview 결과는 운영 보고서에 기록
- 작업 위치: `D:\Persnapse\persnapse-mvp`
- UI 출처: `D:\Persnapse\koin-contact-map\src`의 기존 6개 메뉴 및 보라색 디자인. 원본 레포와 기존 공유용 Production은 수정하지 않는다.

## 결정

Next.js에 기존 프론트 컴포넌트를 이식하고, UI가 공통 Workspace API를 통해 PostgreSQL의 실제 기록을 읽고 저장한다. 별도 Vite 서버와 이중 데이터 저장소를 운영하지 않는다. UI 이식 파일은 `src/features/workspace/ui`, 타입·서버 경계는 `src/domain/workspace` 및 `src/server/db/workspace-repository.ts`에 둔다. 이식 JSX는 allowJs로 유지하며 새 계약과 저장 계층은 TypeScript로 작성한다.

1. 일정/업무, 관계 지도, 인맥 관리, 만남 기록, 명함 등록, 녹음의 6개 메뉴를 유지한다.
2. 인맥은 `persons`, 만남과 참석자는 `interactions`/`interaction_participants`, 검토한 기억은 `memory_statements`를 사용한다. 일반 업무는 새 `workspace_tasks`에 저장한다. 관계에서 생긴 약속인 `action_items`와 혼동하지 않는다.
3. 명시적인 게스트 이름은 만남에만 저장한다. 이름이 같다는 이유로 인맥을 합치거나 게스트를 자동으로 새 인맥으로 만들지 않는다.
4. 사용자 수정은 버전 검사로 보호한다. 오래된 수정은 409로 거절하고 서버 최신값을 다시 읽는다. 화면의 입력 초안은 유지하지만 자동으로 덮어쓰지 않는다.
5. 모든 변경은 원자적 transaction과 요청 UUID 원장으로 처리한다. 서버 확인 전에는 저장 완료나 새 기록을 표시하지 않는다. 응답 유실 시 같은 요청을 재확인하며 새 입력 폼도 동일 엔터티 UUID를 유지한다.
6. 삭제는 보관 처리하고 복원을 지원한다. 검색과 projection은 보관 상태·현재 참석자 관계를 함께 따르며, 만남의 내용/날짜 수정 시 기존 AI 추론을 보관하고 검색에서 제외한다. 수동 확정 기록과 약속은 원본을 보존한다.
7. 날짜 미상은 null, 시각은 한국 시간으로 통일한다. 날짜만 수정하지 않았다면 기존 만남의 정확한 시각을 유지한다.
8. 프로필·메일 초안은 공유 workspace에 저장한다. 개인별 계정/페르소나를 구현한 것으로 표현하지 않는다.

## 제품 경계

Capture → Review → Identity 선택 → Commit → Memory → Recall 흐름을 기존 백엔드 그대로 사용한다. 채팅 입력은 기록 검색이며 자동 저장하지 않는다. 별도 기록 모달에서 검토한 내용을 확정한다. 답변은 저장된 근거와 인물 UUID를 인용하고, 기록된 약속과 AI 제안을 구분한다. 외부 이메일 발송이나 캘린더 등록을 자동 실행하지 않는다.

업무 브리핑은 서버가 현재 미완료 업무를 읽어 생성한다. 클라이언트가 전달한 인맥/업무 목록을 사실로 받아들이지 않는다. 인용한 업무/인물 ID를 응답 후 검증하며 요청량 제한과 실제 제공자 호출 기록을 재사용한다.

명함은 기존 OCR → 필드/맥락 검토 → 확정 → private Storage 흐름을 사용한다. 사진은 인맥 프로필의 정보 탭에서도 확인할 수 있다. 행사 메타데이터는 지원 도메인만 조회하고 결과를 사용자가 적용한다.

녹음의 오디오 파일은 아직 브라우저 세션에 있다. 직접 작성한 인맥 메모만 서버에 저장한다. STT·오디오 서버 보관과 실제 LLM 메일 생성은 이번에 연결할 기존 API가 없으므로 후속 구현 대상으로 남긴다. 메일 UI는 예시 템플릿임을 표시한다.

## 운영 경계 및 영향

- 하나의 서버 workspace를 팀이 공유하는 MVP다. 개인별 인증/RLS 제품 기능을 구현한 상태가 아니다. 기존 Vercel Authentication으로 보호된 Preview에 배포한다.
- UI 화면 설정 이외에 localStorage를 기록 저장소로 쓰지 않는다. 예전 브라우저 샘플 데이터를 자동 이관하지 않는다.
- 초기 GET은 전체 workspace snapshot이다. 6명 검증 범위에서 측정하고, 데이터가 커지면 페이지네이션과 변경분 동기화를 도입한다. 편집 모달이 열린 동안 자동 갱신을 쉬고 포커스/30초 주기로 갱신한다.
- CRUD는 검색 문서를 transaction 내 재구성하지만 유료 embedding을 자동 호출하지 않는다. 변경 후 검색 준비가 필요하면 AI 화면에서 명시적으로 준비한다.
- 기존 백엔드의 `/capture`, `/recall`, `/people` 상세 화면은 검증·상세 조회용으로 유지한다.
- 적용한 migration은 `20261008050000`, `20261008050100`, `20261008050200`이다. 기존 데이터 삭제·seed는 실행하지 않았다.
- Next/ESLint 설정을 16.3.8로 함께 업데이트하고 호환되는 운영 하위 의존성을 갱신했다. 근거: [Next 유지관리자 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j), [수정된 cache 문제](https://github.com/vercel/next.js/security/advisories/GHSA-3w37-wq28-93x7). 운영 의존성 audit와 실제 공격 가능성 평가는 서로 다르다.
