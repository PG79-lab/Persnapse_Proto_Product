# LC100 원근 보정을 OCR 앞 단계에 연결

2026-10-13 사용자 승인에 따라 통합 `/#cards`에서 촬영/파일 선택 → LC100 → 원근 보정 → 2D 이미지 확인 → OCR → 정보 확인 순서로 변경한다. 기존 미커밋 변경은 유지한다.

LC100은 브라우저 Worker의 기존 ONNX/WASM 런타임을 사용한다. 유효한 네 점만 기존 OpenCV 원근 변환기에 전달한다. 자동 감지가 실패하면 OCR을 실행하지 않고 수동 네 점 보정을 제공한다. 잘못 감지된 외곽도 OCR 전 편집할 수 있다. 원본과 보정본을 비교하고 JPEG를 다운로드할 수 있다. 출력 비율은 estimated이며 글자 방향 자동 판정은 포함하지 않는다.

사용자가 채택한 보정본을 기존 display 자산으로 저장하고 새 recipe에서는 이 이미지를 OCR 입력으로 사용한다. 최초 OCR과 재시도 모두 display의 실제 바이트/해시를 사용한다. 기존 canvas-card-v1 기록은 원본 OCR 정책을 유지한다. 별도 DB 마이그레이션 없이 기존 processing_metadata.recipe에 경로를 기록한다. 서버 저장용 원본 압축 정책은 기존 그대로이며 세션의 촬영 File은 유지한다.

현재 OCR 제공자 설정과 필드 확인·Identity 결정·저장 정책은 유지한다. 로컬 3100 테스트 서비스는 실제 LC100/warp와 메모리 내 Mock OCR 응답을 제공하며 외부 AI·DB 저장은 실행하지 않는다. 일반 앱에서는 기존 OCR 환경 설정에 따라 실제 OCR을 실행한다. 원래 설계의 v2 저장 메타데이터·실측 비율·전체 모바일/품질 gate까지 완료한 것으로 해석하지 않는다.
