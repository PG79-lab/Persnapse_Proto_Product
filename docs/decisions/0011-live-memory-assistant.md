# ADR 0011 — 실제 맥락 이해와 근거 기반 회상 연결

> 후속 사용자 요청으로 앱 일/월 누적 한도를 제거했다. 최신 정책과 새 배포 주소는 [사용자 테스트 운영 보고](../operations/user-test-capacity-2026-09-22.md)를 우선한다. 아래 90회 한도 기록은 변경 전 이력이다.

- 날짜: 2026-09-22
- 상태: 사용자 승인으로 구현·원격 DB 적용·보호된 Preview 활성화 및 제한된 실제 검증 완료. 성능·실제 사용자 품질 검증은 미완료.
- 범위: 기존 MVP 안에서 Context → 저장 → 검색 준비 → Recall → 근거·행동·피드백 연결.

## 결정

1. 기존 Luna 구조화 어댑터를 재사용한다. 상대 날짜는 Asia/Seoul 기준으로 해석하며, 기록 시각을 만남 날짜로 대체하지 않는다. 날짜 미상 저장을 위해 interactions.occurred_at의 NOT NULL 해제 migration을 준비한다. 기존 날짜의 사실 여부를 임의로 재분류하거나 기존 데이터를 일괄 수정하지 않는다.
2. Recall live 경로는 질문 구조화 1회 → Voyage query embedding 1회 → 기존 vector(1024) 문서 검색 → Voyage 재정렬 1회 → Terra 근거 기반 답변 1회다. 최대 4회 모델 요청이며 자동 재시도·추가 Agent·자율 tool loop를 도입하지 않는다. 명확화/후보 없음은 조기 종료한다.
3. 기존 Person 검색 projection을 후보 탐색에 재사용한다. 최종 근거는 개별 만남·기억·행동에서 읽는다. 새로운 Graph DB나 작업 큐를 만들지 않는다. 후보 검색 32명, 재정렬 최대 8명, 답변 최대 5명으로 제한한다. 이는 원본의 8개 memory chunk와 동일한 구현이 아니며, 사람 단위 projection 재사용이라는 차이를 명시한다.
4. 만남 ID, 장소, 행사, 주제, 약속 기한을 근거에 보존한다. 응답 schema, 인물별 근거 소속, 조건별 근거 선택, 같은 만남 연결, 만남 날짜와 약속 기한을 검사한다. 텍스트의 의미적 함의까지 자동으로 보증하지 않는다. 실제 모델 반례 평가가 별도로 필요하다.
5. 저장된 약속과 새 AI 제안을 구분한다. 외부 행동 실행은 제공하지 않는다. no_result와 검색 준비 실패·모델 실패를 분리하고 mock으로 조용히 대체하지 않는다.
6. 저장 이후 변경된 검색 문서만 임베딩 처리한다. 처리 중 중복 호출을 줄이고 content hash가 달라진 결과를 반영하지 않는다. 임베딩 실패는 확정 기억 저장을 되돌리지 않는다. 기존 데이터의 검색 준비는 명시적으로 승인된 제한 배치로 진행한다.
7. 다른 embedding 모델은 차원이 같아도 같은 검색 공간으로 취급하지 않는다. 현재 모델과 일치하는 ready 문서만 검색한다. MVP에서는 일부 문서의 검색 준비가 미완료이면 전체 live 검색을 차단한다. 누락된 데이터로 결과 없음을 확정하지 않기 위한 보수적 선택이며, 데이터가 커지면 개선 대상이다.
8. Context·검색·답변·indexing은 DB advisory lock과 호출 예약 기록을 사용하는 공통 일/월 한도를 적용한다. 기본 한도는 0으로 비활성이다. OCR 한도와 별개이며 provider hard quota나 통화 단위 예산 상한은 아니다. 제공자 timeout도 이미 과금되었을 수 있어 예약은 환불하지 않는다.
9. 유료 Recall은 명시적 POST 제출에서만 실행한다. 페이지 조회, 새로고침, 링크 prefetch로 모델을 호출하지 않는다. 버튼 중복 제출을 막는다. 전역 HTTP 요청 멱등성은 별도 구현하지 않았으며, 재전송된 요청도 공통 호출 한도에 포함된다.
10. 입력 탭을 전환해도 초안을 보존한다. 사용자에게 내부 구현 용어보다 검토·저장·검색 준비 상태를 표시한다. 회상 답변 피드백 API와 화면, 전체 표시 시간 관측을 추가한다.

## 제한된 기존 오류 보정

- 날짜·미완료 행동 보너스만으로 무관한 결과를 만들지 않도록 수정한다.
- mock 사전을 확장하지 않는다. 자유 장소·주제 이해는 실제 LLM 평가 대상으로 남긴다.
- General OCR의 이름/회사 후보가 모두 짧은 한글이고 구분 근거가 부족하면 이름을 비워 확인하도록 한다. 올바른 이름·회사를 자동 복원한 것으로 보고하지 않는다.
- 기존 AI/live 과장 표현을 정정한다.

## 현실적인 품질·성능 검증

- 테스트 대역으로 모델 연결·실패·근거 검증을 확인하는 것과 실제 모델 품질을 구분한다.
- Context 5초, Agent 6초는 기존 목표다. 네 번의 모델 요청이 포함되는 live 경로에서 달성을 보증하지 않는다.
- API transport attempt, 토큰(반환된 경우), 단계 지연, 서버 처리 시간, 브라우저 표시 시간을 구분한다. 모델 의미 정확성은 transport success와 다르다.
- 현재 전체 그래프 UI와 음성 입력은 여전히 미구현이며 원본 필수 범위로 유지한다.

## 실제 검증 후 제한된 보완

- 모델 입력의 날짜만 Asia/Seoul +09:00로 표기해 한국 날짜를 UTC 전날로 답한 실제 오류를 보정한다. 저장된 원본 timestamp는 바꾸지 않는다.
- DB와 함수 간 지연을 줄이기 위해 Vercel 함수를 icn1로 지정한다. 기존 DB·보호 정책은 유지하고 새 인프라는 추가하지 않는다.
- 답변은 짧은 한국어 문장으로 유도하고 제안 상세는 별도 필드에 둔다. 강제된 속도 보장이나 모델 의미 정확성 검증으로 취급하지 않는다.
- 실제 관측·조기 명확화 실패·비용 추정·남은 한계는 [검증 보고](../operations/live-memory-verification-2026-09-22.md)에 기록한다.
