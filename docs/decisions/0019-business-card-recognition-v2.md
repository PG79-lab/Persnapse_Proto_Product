# ADR 0019 — 단일 명함 인식 고도화

- 상태: Accepted, 구현 중
- 결정일: 2026-10-11
- 적용 범위: 단일 명함 촬영, 추출 정보 확정, 평면 복원, 시각적 명함 결과

## 맥락

기존 흐름은 촬영·OCR·관계 기억 저장을 한 화면에서 이어 처리했다. 사용자 목표는 정확한 필드 추출과 촬영한 명함에 가까운 시각적 복원이다. 실제 명함 사진 약 20장의 경로와 정답 라벨은 아직 제공되지 않았다. 합성 명함과 공개 문서 평가를 실명함 성능 근거로 사용하지 않는다.

## 결정

1. **단일 명함 우선.** 한 사진 안의 여러 명함 분할은 단일 명함 평가 이후 진행한다.
2. **촬영.** 안내 그리드 없이 후면 카메라를 바로 연다. 브라우저 권한 재요청 여부는 제품이 통제하지 않는다. 가능한 경우 고화질 정지사진을 사용하고 실패하면 전체 비디오 프레임을 저장한다.
3. **추출 확인.** 주요 필드를 수정한 뒤 `OK`를 누르면 추출 정보만 비공개 초안에 확정한다. 인물, 만남, 그래프, 기억은 별도 단계에서 명시적으로 저장한다.
4. **디지털 결과.** 촬영 명함의 글자·숫자·로고·색·배치를 최대한 보존한 평면 복원 이미지를 보여준다. 전체 카드의 이동·확대·스크롤만 제공하며 명함 디자인 편집은 요구하지 않는다. 잘못된 자동 코너는 저장 전 확인하거나 직접 지정한다. 복원 실패 시 촬영 이미지를 유지한다. 확인한 필드와 명함 표면의 인쇄 내용은 분리한다.
5. **속도와 품질.** 정확성을 우선한다. 촬영 확정부터 필드 수정 가능까지 p95 3초는 지향 목표이며 1차 합격 게이트가 아니다. 현재 가능한 범위에서 지연을 줄이고 구간별 시간을 측정한다.
6. **검증.** 실제 명함 약 20장은 오류 유형과 후보 비교를 위한 파일럿이다. 성능 수치나 원본과의 시각적 일치 달성은 실명함 검수 전까지 주장하지 않는다.

## 영향

기존 `original`/`display` 비공개 자산, OCR 비용 예약·캐시·멱등성, 인물 선택·관계 기억 commit 경계를 재사용한다. `card_recognition`에서 평면 복원과 뷰어를 개발하며, 기존 서비스에는 필드 확정 시점과 결과 저장 경계를 추가한다. 원본 디자인 복원 방식의 고도화와 OCR 제공자 선택은 같은 실명함·정답으로 비교한 뒤 결정한다.

세부 설계와 구현 상태: [명함 인식 고도화 계획](../plans/business-card-recognition-v2-proposal-2026-10-11.md).

## 프론트 작업 대상 통일 — 2026-10-12

사용자 지시에 따라 프론트 구현·검증 대상은 `/`의 통합 워크스페이스로 통일한다. 기존 독립 페이지와 전용 헤더·검색 화면은 삭제한다. 기존 URL은 통합 UI로 이동하는 리다이렉트로만 보존하며 검색어와 인물 선택을 전달한다.

명함 기능은 `/#cards`의 `CardImport` → `BusinessCardWorkspace` 경로로만 열린다. 어시스턴트에서도 같은 명함 페이지를 사용한다. 저장 후 프로필·검색 이동은 통합 UI의 콜백을 사용하며 저장된 프로필 명함에도 `CardViewer`를 적용한다. 텍스트 기록과 검색 준비 복구는 통합 어시스턴트가 사용하는 공통 컴포넌트로 유지한다. API·DB·Storage 계약은 기존 경계를 따른다.

브라우저 검증은 통합 UI에서 수행하고 결과에 실제 진입 URL, 응답 mock 여부, DB 쓰기 여부를 명시한다. 이전 `/capture` 검증은 독립 페이지를 사용한 당시 이력이다.
