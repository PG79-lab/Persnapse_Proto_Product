# ADR 0021 단일 명함 외곽 인식과 평면 복원 개선

- 상태: Proposed, 구현 전 설계안
- 작성일: 2026-10-12
- 사용자와 확정한 범위: 단일 명함의 외곽·네 모서리 감지와 원본 이미지 기반 평면 복원

## 맥락

현재 자동 복원은 고정 Canny와 가장 큰 4점 윤곽을 사용한다. 출력 비율은 사진 속 변 길이로 근사하고 전체 이미지를 먼저 축소한다. 수동 보정도 저장된 축소 원본을 사용하므로 모델만 바꿔서는 비율·화질 문제가 해결되지 않는다. 사용자는 정확성·원본 시각 보존을 우선하며 3초는 필드 추출의 지향 목표로 합의했다.

## 제안

1. DocAligner FastViT-T8을 주 검증 후보로 두고 LC100·DocQuadNet을 같은 입력·복원 조건으로 비교한다. 공개 가중치를 우선 재사용한다. 실측 전에 최종 모델을 확정하지 않는다.
2. 학습 모델의 코너 예측에 원본 경계 정밀화·기하 검증·비율 정책·한 번의 원근 변환을 연결한다. OpenCV는 정밀화와 변환에 재사용한다.
3. ONNX Runtime Web과 전용 Worker를 사용한다. WASM 단일 스레드를 기준으로 하며 모델·런타임을 화면 진입 때 준비한다. WebGPU와 양자화는 품질·기기 검증 뒤 비교한다.
4. 첫 복원은 촬영 파일, 채택 후 재복원은 별도 압축 ROI 소스를 우선한다. 이를 위해 nullable source 참조·revision, `restoration_source` variant, 별도 소스 업로드와 v2 복원 메타데이터를 추가하는 안을 채택 대상으로 둔다.
5. 실제 비율을 모르면 근사 미리보기와 사용자 조정을 제공한다. 모든 명함에 한 규격을 강제하지 않고 근사값을 실측값으로 기록하지 않는다.
6. 통합 `/#cards`에서만 연결한다. 복원 계산은 OCR 중 진행할 수 있으나 결과 공개는 필드 OK 이후, 표시 이미지 저장은 사용자의 채택 이후다. 관계 기억 저장은 기존 별도 단계다.
7. 합성·실촬영·기기 성능을 분리 평가한다. 내용 잘림·비율·수동 수정이 먼저이며 속도는 그 뒤에 비교한다. 실촬영 경로는 제공될 때까지 보류한다.
8. [정량 검증 기준](../plans/card-boundary-rectification-benchmark-2026-10-12.md)을 단계별 완료 기준으로 사용한다. 평균 코너 오차 ≤0.35%, 내용 잘림 0건, 수정 없는 채택 ≥95% 등 품질 기준과 기준 기기 반복 복원 p95 ≤4초 등의 성능 기준을 각각 판정한다. 실제 약 20장의 파일럿과 최소 표본을 갖춘 최종 검증을 구분하며 실패·미측정·표본 부족을 PASS로 표시하지 않는다. 촬영→필드 수정 가능 3초는 지향 목표로 유지한다.

## 영향

예상 변경은 `card_recognition` 내부 모듈, 기존 명함 워크스페이스, 복원 service/repository/API, 자산 참조를 위한 migration이다. 별도 AI 분류 호출은 늘지 않는다. 복원 소스를 채택 시 저장하면 카드당 최대 3.2MB의 추가 비공개 저장 공간과 업로드 한 회가 발생한다. 기존 original·display와 v1 메타데이터는 읽을 수 있게 유지한다.

신규 모델·소스 정책은 현재 구현 상태가 아니다. 최종 모델과 제품 기본 전환은 검증 결과에 따라 결정한다. 구현 항목·계약·완료 조건은 [구체 작업 설계](../plans/card-boundary-rectification-design-2026-10-12.md)를 따른다.
