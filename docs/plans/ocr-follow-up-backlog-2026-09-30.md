# OCR 고도화 범위와 후속 개선 목록 — 2026-09-30

## 이번 단계의 확정 목표

사용자는 핵심 기능과 결과 중심의 빠른 개발을 우선한다. 이번 단계는 다음 세 가지에 집중한다.

1. 빠른 명함 인식.
2. 명함 인식과 이름·회사·직책·연락처 구조화 품질의 큰 개선.
3. 촬영·인식한 명함 이미지의 업스케일 및 디지털 카드 UI 변환.

현재는 개발 전 방향 제안 단계다. 아래 구현 방향과 평가 수치는 제안이며 확정 성능이나 개발 완료를 의미하지 않는다. 대규모 검토·필요시 리팩토링은 MVP 최종 마무리 단계에 진행한다.

## 제안하는 최소 구현 흐름

촬영/업로드 → 인식용 이미지 준비 → OCR와 필드 구조화 → 핵심 정보 수정 가능한 카드 표시 → 고해상도 이미지 표시·보존 → 기존 저장 흐름.

- 기존 CLOVA 연결과 저장·검토·안전장치를 재사용한다. General OCR의 규칙만 계속 늘리는 대신, 기존 LLM을 이용한 필드 구조화를 짧은 실제 명함 비교로 검증한다. 공급자·모델 교체는 아직 결정하지 않는다.
- 업로드·저장·인식의 순차 대기를 측정해 줄인다. 추가 모델 호출은 정확도 이득과 지연을 함께 평가하며, 속도 개선을 보장하지 않는다.
- 이미지 보정·확대와 디지털 카드 재구성을 구분한다. 사진을 확대해도 없던 원문을 복원하는 것은 아니다. 이름·연락처는 확인 가능한 인식 결과로 렌더링하고, 생성형 처리로 글자·숫자를 바꾸지 않는다.
- 디지털 카드는 구조화된 내용을 선명한 텍스트로 표시하고 보정한 실제 명함 이미지도 확인할 수 있도록 한다. 원본 디자인 그대로 재현할지에 대한 추가 요구는 아직 확정하지 않는다.
- 우선 승인된 실제 명함 소수로 변경 전후를 같은 조건에서 비교한다. 핵심 필드 정확도, 수정 필드 수, 제출부터 수정 가능한 카드가 뜰 때까지 시간을 확인한다. 3~5초는 목표이며 달성 사실이 아니다. 소수 샘플로 전체 정확도나 p95를 보증하지 않는다.

## 후속 수정·개선 목록

아래는 기존 읽기 전용 검토에서 나온 항목이다. 이번 세 가지 목표에 직접 필요한 최소 부분만 선택할 수 있으며, 전체를 이번 개발 범위에 포함하지 않는다.

| 영역        | 후속 항목                                                                | 기존 확인 상태                                                               |
| ----------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 입력 형식   | HEIC 지원, 양면 명함 연결, 한 사진 속 다중 명함 분할                     | HEIC·다중 명함 분할 미지원. 양면 연결은 후속 후보                            |
| 촬영 품질   | 자동 경계 검출, 원근·회전 보정, 사용자 잘라내기, 흐림·반사 감지          | 현재 고정 가이드와 중앙 자르기, 제한된 Canvas 보정                           |
| 원본 보존   | 업로드 원본 바이트와 재압축 이미지 구분 및 보존 정책                     | 현재 original도 JPEG 재압축되므로 파일 원본과 다름                           |
| 인식 근거   | 필드별 OCR 신뢰도·좌표·출처 보존, 이미지와 필드 연결 강조                | 현재 최종 Draft에 필드별 신뢰도·좌표가 없음                                  |
| 구조화 확장 | 다국어·복잡한 배치·연락처 유형, 전용 Name Card OCR 비교                  | General 규칙 기반 구조화. 전용 응답 adapter는 있으나 현재 원격 활성화 미확인 |
| 처리 UX     | 카메라 창 종료 시점, 단계별 상태·취소·재시도, 지연 문구 정합성           | 코드상 카메라가 OCR 완료를 기다림. 12초 안내와 전체 요청 제한이 다름         |
| 카드 UX     | 세로·특수 비율, 오버레이 가림, 원본 확대·비교, 불확실 필드 강조          | 고정 가로 비율·이미지 위 텍스트 존재. 실제 사용성 영향은 미검증              |
| 등록 흐름   | 검토 단계 축소, 명함 우선 저장 후 맥락 보완                              | 추가 범위 결정이 필요한 제품 개선 후보                                       |
| 성능 계측   | 전처리·전송·Storage·DB·OCR·구조화·렌더링 구간 측정, 충분한 p50/p95 표본  | 기존 API 측정과 사용자 전체 대기시간을 구분해야 함                           |
| 평가 확장   | 촬영 기기·조명·언어·배치별 데이터셋, 필드 정확도·수정량·실패율 회귀 평가 | 기존 합성 시험은 실제 명함 품질을 대변하지 않음                              |

## 유지할 경계와 미해결 사항

- 서버 전용 키, 비공개 이미지, 사용자 수정 우선, 명시적 인물 연결, 중복 저장·호출 방어는 유지한다.
- 실제 명함의 외부 전송은 이미지·OCR 텍스트·전송 제공자를 설명하고 필요한 승인 범위 안에서 진행한다. 이번 문서 작성에서는 API 호출·DB 변경·배포를 하지 않는다.
- SEARCH_NOT_READY 장애는 해결되지 않았다. 이번 OCR 품질 개선으로 자동 해결된다고 보고하지 않으며, 실제 명함 기반 회상 검증 전에 복구한다.
- 기준 구현은 777e111, 인계 문서 커밋은 53ca964다. 9월 26일 검토는 로컬 코드·문서 확인이며, 실제 명함 API 및 실기기 품질 시험은 아니었다.
