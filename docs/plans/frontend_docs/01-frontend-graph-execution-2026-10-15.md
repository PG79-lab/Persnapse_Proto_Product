## 1. 세션 시작점과 문서 책임

### 2026-10-17 작업 우선순위 변경

사용자가 기존 visual design의 부족을 지적하고 “레퍼런스 visual design을 reverse engineering 관점으로 분해”, “기능/충돌/스모크 테스트 등은 정말 최소화”, “visual design에만 집중”하도록 요청했다. 이번 실행은 이 지시를 우선하여 W03·W04의 외형을 다시 구성하고 기존 VD02/03 진입 화면의 시각 정제를 진행했다. 전체 기능 구축 단계의 완료로 계산하지 않는다.

- 이번 검증 범위: 변경 코드의 lint, 실제 브라우저 렌더링과 화면 조작·캡처. 전체 unit/E2E/build 파이프라인은 재실행하지 않는다. `AGENTS.md`의 큰 단계 전체 검증보다 이번 사용자의 명시적 범위 지시를 우선한 것이다.
- 다음 작업도 사용자 피드백을 먼저 받아 visual refinement를 이어갈 수 있다. W06 이후 API/서버 작업으로 자동 전환하지 않는다.

V3a는 기존 snapshot의 인물·만남·참석에 한정한다. V3b는 읽기 API 후의 행사·주제·소속·공유 맥락 검토다. V4a/V5a는 기존 계약을 활용한 시안 검토, V4b/V5b는 실제 연결 검증이다. 선행 계약이 없으면 해당 검토를 `계약 의존`으로 남기며 통과로 계산하지 않는다.

**핵심 3화면 Gate:** W03·W05에서 시각 방향을 비교하고 W07~W09에서 데이터·동작을 확인한 VD01/02/03을 Persnapse 기준 화면으로 채택한다. 각각 desktop/mobile 실제 캡처, 사용자/디자인 및 개발/QA 리뷰, 수정 이력, 차단·필수 문제 0건이 있어야 W10으로 확장한다. 사용자에게 이 비교 결과를 검토 가능한 묶음으로 보고하되 매 간격 조정마다 승인을 요청하지 않는다.

P0 필수 기능의 `계약 의존`은 W11 통과가 아니다. 지원 불가라면 실제 제한을 해결하거나 사용자의 명시적 범위 변경을 기록한다. P1/후속은 사유를 적고 `해당 없음`으로 분리할 수 있다.

## 4. 작업 카드와 세션 인수인계

각 W 작업의 첫 기록은 다음 양식으로 작성한다. 아래 경로는 **구현 단계 생성 제안**이며 아직 존재하는 산출물이 아니다.

```markdown
# W03 / iteration-01 — 인물 선택 시 근거를 빠르게 읽기

- 상태: 준비 / 진행 / 검증 / 완료 / 의존 대기
- 결정: D01·D02 승인 기록, 또는 미승인 범위
- 기준: worktree / branch / HEAD / baseline manifest / 현재 diff 식별
- 목표와 문제 1~3개:
- 선행 작업·계약·현재 지원 데이터:
- 설계 절 / VD·VS·GS·T ID / reference B ID:
- 이번 변경 대상 / 보존할 동작 / 제외 범위:
- fixture 버전 / 고정 시각 / 재현 절차:
- 검사 명령 / 기대 결과 / 실제 결과:
- 전체·crop·전환 증거 경로:
- 사용자·디자인 리뷰 / 개발·QA 리뷰 / 수정·재검증:
- 미해결 항목·영향 / 최종 판정 / 다음 작업:
```

작업 기록은 `docs/operations/frontend-graph-runs/<run-id>.md`, 캡처는 Atlas 제안 경로를 사용한다. 이 실행 문서의 작업 표를 복제해 여러 상태 원장을 만들지 않고 각 작업의 최신 기록 링크·상태만 연결한다.

세션 종료 전 `완료 작업 / 진행 작업의 실제 변경 / 검사·증거 / 남은 문제 / 다음에 실행할 한 작업 / 실행 중 서버의 소유 PID·port`를 기록한다. 다음 세션은 cwd·branch·baseline·미커밋 diff를 확인하고 완료 작업을 재생성하지 않는다. 예전 다른 worktree의 완료 보고를 이 공간의 증거로 재사용하지 않는다.

현재 작업 상태: W00 환경·기준 캡처, W01 토큰, W02 Graph 어댑터·탐색 상태, W03 Graph·Inspector, W04 확장·접기·복귀를 구현하고 검증 중이다. [실행 기록](../../operations/frontend-graph-runs/2026-10-16-initial.md)의 실제 검사 결과와 미해결 항목을 확인한다. W05–W11 및 VD01–03 전체 Gate는 완료되지 않았다.

## 5. 격리 실행·검증 계획

### 5.1 W00 준비 조건

- 이 worktree에서 Node `24.x`와 lockfile 기준 의존성을 준비한다. 설치 전 package scripts·적용 AGENTS·Next 로컬 가이드를 확인한다. 원본 worktree의 `node_modules`·`.next`를 공유하거나 복사하지 않는다.
- `.env.local`은 복사하지 않았다. mock 테스트에 필요한 설정 키·server render의 요구를 `.env.example`과 현재 코드에서 확인한다. 실제 비밀 값은 기록하지 않는다. 기본 visual 검증은 합성 데이터·mock이며 live 모델·OCR·STT·DB 쓰기 검증과 분리한다.
- 후보 port는 `4315`다. 사용 중이면 다른 빈 port를 택하고 run 기록에 남긴다. 기존 프로세스를 임의 종료하지 않는다.
- **구현 예정 파일:** `playwright.graph.config.ts`, `tests/fixtures/frontend-graph.ts`, `tests/e2e/graph-visual.spec.ts`. 아직 존재하거나 실행 검증된 파일이 아니다. 기존 fixture/테스트를 재사용해 책임이 중복되면 경로 제안을 조정하고 실제 위치를 기록한다.

### 5.3 명령 프로파일

2026-10-16 W00에서 전용 config·fixture를 구현했다. 아래는 현재 실행 명령이다. UI 서버 4315와 잘못된 STT 입력의 실제 validation 전용 서버 4317을 각각 소유한다. 4317은 합성 설정·지원하지 않는 모델로 provider 실행을 차단하며, 일반 UI 서버는 모든 미등록 API를 차단한다. 상세 격리 경계는 [실행 기록](../../operations/frontend-graph-runs/2026-10-16-initial.md)을 따른다. 기존 `npm run test:e2e`는 기본 config를 사용하므로 이 격리 프로파일의 대체가 아니다.

```powershell
# cwd: D:\Persnapse\worktrees\persnapse-frontend-graph-review
$env:PLAYWRIGHT_PORT = '4315'
npm run build
npx playwright test --config=playwright.graph.config.ts
```

작업 중에는 변경과 관련된 단위·통합·브라우저 검사를 우선한다. 큰 단계 종료에는 AGENTS의 lint·typecheck·unit·build를 수행하고 최종 `npm run verify` 및 격리된 관련 E2E를 완료한다. 설정 적용 후 기존 E2E 전체도 같은 격리 서버에서 수행할 수 있게 config의 testMatch를 구성한다. 새 테스트만 통과하고 기존 회귀를 생략하지 않는다.

기존 실패는 W00에서 재현·원인·영향을 기록한다. 기준 상태에서도 실패했다는 이유로 관련 회귀를 무시하지 않는다. 관련 없는 사용자 파일을 전역 formatter로 변경하지 않고 변경 문서·코드만 포맷한다. format 검사와 제품 검사를 구분한다.

### 5.4 실시간 미리보기와 사용자 검토 방식

2026-10-16 작업 방식 반영 후 같은 날 별도 구축 착수 요청을 받았다. 현재 승인·진행 상태는 2·4장과 실행 기록을 따른다.

1. **착수 후 미리보기부터 준비:** W00에서 이 worktree 전용 개발 서버와 합성 데이터 미리보기 환경을 준비한다. 실제 응답과 화면 렌더링을 확인한 뒤 클릭 가능한 로컬 URL, 시작 화면, 데이터 모드, 현재 구현 범위를 사용자에게 먼저 전달한다. 준비 중에는 의존성 설치·환경 확인 등 화면이 아직 보이지 않는 이유와 진행 상태를 알린다.
2. **브라우저에서 변경 확인:** 사용자가 URL을 열어 둔 상태에서 저장한 코드 변경을 개발 서버의 hot reload로 확인하게 한다. 연결·컴파일이 정상인 동안 변경이 반영되며, 전체 새로고침·상태 초기화·서버 재시작이 필요한 경우 이를 안내한다. 임시 오류나 미완성 화면은 현재 작업 상태로 설명한다.
3. **진행 상황 공유:** 작업 시작 시 이번 목표와 관찰할 화면을 알리고, 작업 중에는 완료 내용·남은 문제·다음 확인 지점을 간결하게 공유한다. 장시간 작업 중에는 60초 이상 설명 없이 진행하지 않는다. 사용자 피드백은 현재 작업 카드에 기록하고 범위 안의 수정에 반영한다.
4. **핵심 3화면부터 비교:** VD01 Graph 탐색·Inspector, VD02 Recall·근거, VD03 입력 검토·저장을 먼저 보여 준다. 각 단계에서 현재 화면 전체·crop, 변경 전후, 관련 Atlas B ID 이미지와 채택·변형한 부분을 묶어 비교한다. 합성 데이터·mock으로 보는 단계와 실제 계약 연결까지 검증된 단계를 표시한다.
5. **실시간 관찰을 검증 증거로 보완:** 일반 탐색은 사용자가 직접 조작할 수 있게 제공하고, 지연 응답·저장 충돌·오류·모바일·키보드 상태는 재현 절차와 별도 캡처 또는 테스트 결과로 보고한다. 실시간으로 화면이 보인다는 사실만으로 기능·시각 Gate 통과를 판정하지 않는다. 검토·반복 개선·완료 판정은 3·6·7장 기준을 적용한다.

**개발 서버와 검증 서버 운영:** 개발 미리보기에는 별도 빈 port를 배정하고, 5.2의 production E2E 서버와 URL·PID·실행 목적을 구분한다. Playwright의 `reuseExistingServer = false`는 유지한다. 두 서버가 동일 `.next` 산출물을 동시에 변경하지 않도록 설치된 Next 버전의 출력 경로 분리 지원을 확인해 설정하거나, 검증 중 미리보기를 잠시 중단하고 복구한다. 중단·주소 변경은 사용자에게 알린다. 브라우저 테스트용 route mock만으로 일반 미리보기까지 합성 데이터로 동작한다고 간주하지 않고, 일반 브라우저에서도 동작하는 데이터 주입·외부 호출 격리를 확인한다.

run 기록에는 `미리보기 URL / cwd·branch / 소유 PID·port / 시작 명령 / 데이터 모드·fixture 버전 / 현재 W·VD / 알려진 미완성 상태 / 최근 비교 증거 / 서버 실행·중단 상태`를 남긴다. 서버가 살아 있을 때만 접속 가능하다고 안내하며, 세션 종료 시 실행 상태와 재시작 방법을 인계한다.

## 7. 회귀와 완료 판정

수정 순서는 **기능·데이터·입력 손실 차단 → 접근성·가독성·상태 보존 → 공통 컴포넌트·정렬·밀도 → 미세 모션**으로 모든 문서에 공통 적용한다.

- `/` 기본 진입 기대값은 D01 승인 후 변경한다. 업무 과업 테스트는 `/#todos`로 명시 이동시켜 검증을 보존한다. 업무 관련 assertion을 삭제해 새 Graph를 통과시키지 않는다.
- 기존 8명 paging·만남 숨김 규칙은 새 slice 계약에 맞게 기대를 갱신하되 생략 범위 안내·추가 접근 검증은 유지한다. CSS class만 바뀌면 가능한 역할·이름·명시 대상 ID 기반으로 검증한다.
- 기록된 관계·원문·저장 계약은 screenshot 외 단위/통합/E2E 결과가 필요하다. visual 검토는 실행 중 화면 전체와 crop을 실제 열어 확인하고 발견·수정·재검증을 기록한다.
- 판정은 `통과 / 수정 필요 / 계약 의존 / 해당 없음(이유)`이다. 필수 항목 미검증·의존 대기·실패를 평균 디자인 점수로 상쇄하지 않는다.
- 반복은 발견한 문제를 해결하고 관련 회귀가 통과하면 종료한다. 이후는 구체적 새 문제가 있을 때만 반복하며 취향에 따른 무제한 미세 조정을 하지 않는다.
