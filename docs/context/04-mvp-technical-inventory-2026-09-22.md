## 1. 현재 기술적 도달점

**명함 또는 텍스트를 입력하고, 사람이 확인한 관계 기억을 저장한 뒤, 실제 AI로 사람·근거·다음 행동을 회상하고 피드백을 남기는 흐름이 구현돼 있다.** 보호된 Preview의 합성 텍스트 입력 → 수정 → 저장 → 회상 → Profile → 피드백 경로는 실제 API로 통과한 기록이 있다. 실제 명함 OCR도 별도로 연결·검증됐다.

현재 결과물은 **공유 Workspace를 사용하는 팀 내부 테스트용 웹 프로토타입**이다. 음성·기본 관계 그래프를 포함한 원본 MVP 전체 완료, 사용자별 인증·데이터 격리 제품 완성, 실사용 정확도·성능 목표 달성을 의미하지 않는다.

## 3. 구현된 핵심 처리 흐름

### 3.1 텍스트 → 확정 관계 기억

1. `/capture`에서 메모를 제출하면 idempotency key와 원문을 가진 Capture를 만든다.
2. live 모드에서 Luna가 인물 힌트, 만남, 주제, 기억, 약속을 Draft schema로 구조화한다.
3. 사용자가 추정 항목과 내용을 수정하고, 새 인물 생성 또는 기존 인물 연결을 명시적으로 선택한다.
4. DB 트랜잭션으로 인물·소속·만남·주제·기억·행동·출처를 확정한다. 이미 확정한 Capture의 재요청은 기존 결과를 반환한다.
5. 확정 후 사람별 검색 문서를 재구성하고 Voyage 임베딩을 준비한다.
6. Profile과 Recall로 이어진다. 검색 준비 실패는 확정 기억을 취소하지 않으며 별도 상태로 반환한다.

- Capture 상태: `draft → review → committed`, 실패 시 `failed` 및 제한된 재시도 전이. `committed`는 종료 상태다.
- 원문·모델 초안·사용자 수정값을 구분한다. 이름만 같다는 이유로 자동 병합하지 않는다.
- 만남 날짜가 모르면 `null`을 허용한다. 실제 구조화는 한국 시간 기준 상대 날짜와 약속 기한을 구분하도록 구성돼 있다.
- **원자성의 범위는 확정 관계 데이터 트랜잭션이다.** 외부 OCR·Storage 업로드·후속 임베딩까지 하나의 DB 트랜잭션은 아니다.

### 3.2 명함 이미지 → 연락처·맥락·디지털 명함

1. 웹 카메라 또는 JPEG·PNG·WebP 파일을 선택한다. 파일 입력은 최대 10MB, 대기열은 최대 5개다.
2. 브라우저 Canvas에서 JPEG 변환·크기 조정·압축·약한 대비 보정을 수행한다. 작은 이미지는 최대 2배 범위로 보간 확대한다.
3. 보존용·표시용 이미지 두 개를 private Storage에 저장한다. 전송 합계는 4MiB 미만으로 제한한다.
4. 표시용 이미지에 Clova OCR을 실행하고 이름·회사·직책·연락처 후보를 검토 화면에 제시한다.
5. 사용자 수정 연락처와 별도 메모의 AI 구조화 결과를 합치고, 인물 선택 후 관계 기억과 디지털 명함을 확정한다.
6. Profile에서 명함 이미지/정보 전환, 전화·이메일·웹사이트 링크와 원본 자산 삭제 기능을 제공한다.

- 실제 연결된 OCR은 Clova다. Google fallback 배정만으로 실제 대체 OCR 구현·검증 완료를 주장하지 않는다.
- General OCR 응답의 필드 분류에는 규칙이 사용된다. 이름·회사 구분이 불확실하면 이름을 비워 확인을 유도하는 보정이 있다.
- 같은 이미지의 추출 결과 재사용과 동시 중복 호출 방어가 있다.
- 코드의 `original` 자산도 브라우저에서 재인코딩·크기 조정된 이미지다. 사용자가 선택한 파일의 바이트 원본 보관으로 설명하지 않는다.
- 자동 명함 경계 검출·한 사진 속 여러 명함 분리·흐린 글자 AI 복원은 구현 범위가 아니다. 카메라 중앙 가이드 영역 자르기와 일반 이미지 보정을 제공한다.

### 3.3 질문 → 사람·근거·판단·행동

live Recall은 다음 고정 순서이며, 정상 전체 경로는 최대 4회의 모델 요청이다.

| 순서 | 처리                                     | 산출물·제한                                                                       |
| ---- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| 0    | Workspace 검색 준비 상태 확인            | 누락·실패·다른 모델의 문서가 있으면 검색을 막고 별도 오류                         |
| 1    | Luna 질문 이해                           | 최대 6조건, 인물/만남 범위, 같은 만남 조건, 만남 날짜/행동 기한, 명확화 필요 여부 |
| 2    | Voyage query embedding → PostgreSQL 검색 | 1024차원 벡터 검색과 명시적 인물·미완료 행동 후보 결합, 최대 32명                 |
| 3    | Voyage reranking                         | 최대 8명 선택 후 해당 인물의 확정 원기록 조회                                     |
| 4    | Terra 답변 생성 → 서버 검증              | 최대 5명, 선택 근거·조건별 근거·판단 이유·새 제안                                 |

- 명확화가 필요하거나 후보가 없으면 중간에 종료한다.
- 최종 답변은 사람별 검색 요약만으로 만들지 않고 개별 만남·기억·행동 근거를 다시 읽는다.
- 인물-근거 소속, 조건별 근거 키, 같은 만남 연결, 날짜 범위, 인용한 약속·제안 연결을 검사한다. 이는 자연어 의미 정확성 전체를 보증하는 장치는 아니다.
- 결과 상태는 `resolved`, `ambiguous`, `no_result`다. 모델 실패·검색 준비 실패는 결과 없음과 구분하고 mock으로 조용히 대체하지 않는다.
- 저장된 약속과 새 AI 제안은 별도 필드·UI로 표시하며 모두 자동 실행하지 않는다. 예약 알림·자율 리마인더 기능은 없다.
- 페이지 조회·새로고침·prefetch가 아니라 사용자의 명시적 POST 제출에서 호출한다. 화면 중복 제출 방지는 있으나 전역 Recall HTTP 멱등성은 없다.

근거: [Recall 분기](../../src/server/application/recall-service.ts), [live 실행 순서](../../src/server/application/live-recall-service.ts), [provider 호출](../../src/server/ai/assistant-provider.ts), [근거 검증 계약](../../src/domain/recall/assistant-contract.ts).

| 인물·소속      | `persons`, `person_attributes`, `organizations`, `affiliations`, `business_cards`    | 인물 정체성, 연락처, 조직·소속 이력, 확정 명함             |
| 만남·주제      | `events`, `interactions`, `interaction_participants`, `topics`, `interaction_topics` | 행사·만남, 참여 인물, 대화 주제 연결. 장소는 만남의 필드   |
| 확정 기억      | `memory_statements`, `action_items`, `provenance_records`                            | 기억·관심·사실, 약속·후속 행동, 출처·검증 상태             |
| 검색           | `memory_documents`                                                                   | 사람 단위 검색용 파생 문서, 내용 해시, 벡터·모델·준비 상태 |
| 질의·평가      | `queries`, `query_evidence`, `feedback`, `golden_query_cases`                        | 질문, 반환 근거, 사용자 평가, 합성 기준 사례               |
| 실행·호출 방어 | `ai_runs`, `ai_call_reservations`, `ocr_provider_calls`                              | 모델 실행 관측, 단기 호출 예약·중복 방어 이력              |

인물 ↔ 소속 ↔ 조직, 인물 ↔ 참여 ↔ 만남 ↔ 행사·주제, 인물/만남 ↔ 기억·행동, 확정 정보 ↔ 출처의 연결이 있다. 관계가 저장된 것과 이를 시각화하는 Graph UI 구현은 별개다.

검색 문서는 확정 데이터에서 다시 만들 수 있는 파생 데이터다. 임베딩은 `pending / processing / ready / failed` 상태를 가지며 내용 해시가 달라진 오래된 결과를 반영하지 않는다. 현재 모델과 같은 모델의 ready 문서만 검색한다. 일부 인물의 준비가 끝나지 않아도 전체 live 검색을 차단하는 보수적 구현이므로 사용자 체감 가용성에는 한계가 있다.

Workspace를 포함하는 복합 참조·RLS 정책이 마련돼 있다. 다만 앱은 서버의 `APP_DEFAULT_WORKSPACE_ID`와 서버 자격증명을 사용하는 공유 프로토타입이므로 **사용자별 로그인·멤버십·격리가 완성된 제품으로 표현하지 않는다.**

## 6. 실행 모드·배포·호출 정책

### 실제 연결과 설정상의 준비 구분

- 최신 배포 기록은 `AI_ROUTING_MODE=live`, `BUSINESS_CARD_OCR_MODE=live` 조합이다. Luna·Voyage·Terra와 Clova가 각각 제품 경로에 연결돼 있다.
- 기본 배포 정책은 여전히 mock Context이며, `previewEnvironmentPolicy(true)`의 명시적 live 선택으로 OpenAI/Voyage 키와 live 모드를 추가한다. 현재 로컬 환경값은 이번에 읽거나 변경하지 않았다.
- transcription·quality agent·complex reasoning·여러 fallback은 모델 배정 파일에 존재하더라도 현재 사용자 흐름에서 모두 실행되는 기능이 아니다.
- 최신 기록된 배포: [2026-09-22 Preview](https://persnapse-14o1mh4mz-choeseyong180-8216.vercel.app), ID `dpl_BKzHSSDKsqy36y8uvnExbR73mSSd`. 기존 확인은 READY / Preview / icn1이며 현재 원격 상태를 다시 조회한 값은 아니다.
- Vercel All Deployments 보호, 서버 전용 키, 비인증 요청 302 확인 기록이 있다. Production은 자격증명 없는 정적 bootstrap으로, 실제 MVP Production 운영과 다르다.

### 최신 단기 호출 제한

| 대상                                   | 구현된 한도·범위                          | 동작                                                      |
| -------------------------------------- | ----------------------------------------- | --------------------------------------------------------- |
| AI 구조화·임베딩·질문 이해·재정렬·답변 | Workspace 전체 최근 60초 모델 요청 60회   | DB advisory lock으로 집계·예약. 초과 시 429 / Retry-After |
| 명함 OCR                               | 제공자 범위 최근 60초 20회, 최소 1초 간격 | 이미지·작업 중복 방어와 호출 원장 유지                    |
| 누적 사용량                            | 앱 일·월 누적 상한 제거                   | 과거 이력은 보존하며 차단 기준으로 쓰지 않음              |

회상 1회는 최대 4요청, 새 텍스트 구조화·임베딩 후 회상까지 최대 6요청을 사용한다. 따라서 위 숫자는 사용자 클릭 수·동시 사용자 수·보장 처리량이 아니다. 제공자 잔액·요금·속도 제한과 금액 hard quota는 별개이며, Naver 제공자 quota·예산 알림 검증은 남아 있다.

현재 live 경로는 자동 재시도를 추가하지 않는다. 각 모델 요청은 timeout과 입력·출력 크기 제한을 적용한다. 전체 흐름의 모델 호출을 한 번에 예약하는 구조가 아니어서 중간 제한으로 검색 준비나 답변이 실패할 수 있다.

팀 공유 자료에서 사용할 수 있는 핵심 문장은 다음과 같다.

> Persnapse MVP는 명함·텍스트 입력을 사용자가 확인한 관계 기억으로 저장하고, 실제 AI가 사람과 근거를 찾아 판단 이유·후속 행동을 제안하는 웹 흐름을 구현했다. 보호된 Preview에서 합성 텍스트의 전체 흐름을 검증했고, 명함 OCR도 별도로 실제 연동했다. 음성·관계 그래프와 실사용 품질·성능 검증은 남아 있다.

향후 시스템 그림의 사실 기준은 **브라우저 / Next.js 서버 / PostgreSQL·pgvector / private Storage / Clova·OpenAI·Voyage**와 위 3개 처리 흐름이다. 새 기능·이미지 제작·외부 공유는 이번 정보 정리 범위에 포함하지 않았다.
