## 1. 현재 가장 강하게 성립하는 제품 정의

Persnapse의 핵심은 연락처를 더 잘 저장하는 것이 아니라, 비즈니스 관계에서 생기는 맥락을 장기 기억으로 축적하고 필요한 순간 회상해 다음 행동으로 연결하는 것이다.

이를 구성하는 중심 전환은 다음과 같다.

- Contact Management에서 Relationship Management로
- 정적인 인물 정보에서 시간에 따라 변화하는 관계 맥락으로
- 정보 저장에서 회상과 행동으로
- 개별 AI 기능에서 신뢰 가능한 관계 기억 시스템으로

현재 자료 전체를 관통하는 가장 안정적인 표현은 **Business Relationship Memory**이며, 이를 지탱하는 개념적 구조가 **Temporal Business Context Graph**다.

## 2. 해결하려는 핵심 문제

사용자가 잃는 것은 전화번호나 이메일보다 관계가 만들어진 이유와 이후의 변화다. 핵심 손실은 다음과 같이 묶인다.

- 사람의 정체와 현재 상태
- 만난 시점·장소·사건
- 소개 경로와 관계 형성 배경
- 대화 주제, 관심사와 의도
- 프로젝트나 사업 기회와의 연결점
- 마지막 상호작용과 약속
- 지금 취해야 할 후속 행동

따라서 Persnapse가 해결해야 하는 문제는 단순 검색 실패가 아니라 **관계 맥락의 소실로 인해 적절한 사람을 기억하고 활용하지 못하는 문제**다.

## 3. 핵심 제품 루프에 대한 해석

자료에서 합의도가 가장 높은 루프는 다음과 같다.

> CAPTURE → CONTEXT → MEMORY → RECALL → ACTION

각 단계의 역할은 명확히 구분된다.

| 단계    | 본질적 역할                                           |
| ------- | ----------------------------------------------------- |
| Capture | 관계에 관한 원재료를 낮은 마찰로 획득                 |
| Context | 비정형 입력을 사람·사건·관계·의도 단위로 해석         |
| Memory  | 출처와 시간성을 가진 장기 관계 기억으로 축적          |
| Recall  | 현재 질문과 상황에 맞는 사람 및 관계 이유를 회상      |
| Action  | 회상 결과를 연락, 준비, 소개, 일정 등의 행동으로 전환 |

이것은 일회성 직선 흐름보다 순환 구조로 이해하는 편이 정확하다. Action 이후 발생하는 연락과 미팅은 다시 Capture되는 새로운 Interaction이 되고, 기존 관계의 상태와 기억을 갱신한다.

MVP의 제품 가치는 어느 한 단계의 완성도가 아니라 이 루프가 끝까지 닫히는 데 있다. 특히 자료가 반복해서 강조하는 가치 발생 지점은 Capture가 아니라 Recall이다.

## 4. 개념적 정보 구조

현재 자료에서 반복적으로 등장하는 핵심 개체는 다음과 같다.

- Person
- Company
- Event / Meeting
- Interaction
- Introduction
- Project
- Topic / Interest
- Memory / Note
- Next Action

이 목록은 아직 구현 스키마가 아니라 제품이 기억해야 할 세계의 개념 지도다. 중요한 것은 개체 수보다 다음 세 속성이다.

1. **관계성**: 정보는 고립된 필드가 아니라 사람·사건·프로젝트 사이의 연결로 의미를 갖는다.
2. **시간성**: 소속, 직책, 관심, 관계 강도와 다음 행동은 시간에 따라 달라진다.
3. **근거성**: 입력 출처, AI 추론, 사용자 확인과 수정 이력이 구분되어야 신뢰 가능한 기억이 된다.

따라서 Context Graph는 화면에 보이는 그래프보다 먼저 존재하는 제품의 의미 구조다. 그래프 시각화는 그 구조를 탐색하는 가능한 인터페이스 중 하나다.

## 5. Identity와 Memory의 신뢰 경계

두 자료가 일관되게 강조하는 확정 원칙은 다음과 같다.

- Person은 이름 문자열이 아니라 독립 Identity다.
- 같은 이름을 근거로 사람을 자동 병합하지 않는다.
- AI는 추출하고 후보를 제안하지만 중요한 Identity 결정은 사용자가 확인한다.
- 사용자가 확인하거나 수정한 사실은 AI의 과거 추론보다 우선한다.
- 기억과 관계는 가능하면 출처, 시점, 추론 여부와 확인 여부를 보존한다.

이는 단순한 데이터 품질 정책이 아니라 제품 가치의 전제다. 잘못 연결된 기억은 일부 정보가 없는 것보다 더 큰 피해를 만들며, Recall에 대한 신뢰 자체를 무너뜨릴 수 있다.

따라서 Persnapse에서 Trust는 나중에 추가하는 보조 품질이 아니라 Core Loop 전체에 걸친 제품 속성으로 이해해야 한다.

## 6. AI의 제품 내 역할

AI의 역할은 네 층으로 구분된다.

1. **Structure**: 비정형 입력에서 관계 맥락을 추출하고 구조화
2. **Recall / Retrieval**: 자연어 의도를 사람·시간·관계 맥락에 연결
3. **Reasoning**: 현재 목표와 관계 자산 사이의 유용한 연결을 판단
4. **Action**: 후속 연락, 미팅 준비, 소개와 관계 재활성화로 연결

이 중 앞의 두 층이 현재 제품 정체성에 가장 직접적이다. Reasoning과 Action은 장기 방향과 연결되지만, 사용자의 통제를 벗어난 완전자동 Agent는 명시적으로 경계하고 있다.

AI는 기억의 주인이 아니라 구조화·회상·판단을 돕는 계층이며, 중요한 사실과 Identity에 대한 최종 권한은 사용자에게 있다는 해석이 일관된다.

## 7. 초기 사용자와 가치 가설

초기 사용자로 가장 명확하게 반복되는 집단은 Sales / Business Development다. 이들은 다음 조건을 동시에 가진다.

- 외부 만남이 잦다.
- 관계 맥락의 소실 비용이 크다.
- Follow-up 누락이 업무 성과에 직접 영향을 준다.
- 회상과 행동 개선의 효용을 비교적 빠르게 확인할 수 있다.

Founder, Consultant, Freelancer, Investor 등은 같은 문제를 공유하는 확장 후보로 보인다. Team Relationship Graph는 장기 확장 방향이며 현재 개인 관계 기억의 가설과 분리해서 다뤄야 한다.

## 8. MVP에 대해 현재 이해할 수 있는 수준

현재 자료가 말하는 MVP는 기능 묶음보다 **하나의 완결된 관계 기억 경험**이다.

- 사람과 관계 맥락을 쉽게 입력한다.
- AI가 구조화를 돕고 사용자가 중요한 결정을 확인한다.
- 시간이 지난 뒤 자연어 또는 탐색을 통해 정확한 사람과 관계 이유를 찾는다.
- 결과가 현재 필요한 행동으로 이어진다.

핵심 성공 장면은 “명함이 잘 인식된다”가 아니라 “잊고 있던 사람을 정확한 맥락과 함께 되살려 지금의 행동으로 연결한다”다.

다만 자료에 등장하는 명함 다중 촬영, 음성, 자연어 검색, 3D 그래프, 일정과 리마인드가 모두 MVP 필수 범위로 확정된 것은 아니다. 이들은 Core Loop를 구현할 수 있는 후보 경험이며 이후 제품 정의 단계에서 필수성과 우선순위를 따로 검토해야 한다.

## 9. 기능과 본질을 혼동하지 않기 위한 경계

다음 구분은 현재 제품 정체성을 지키는 핵심 장치다.

| 요소         | 제품 내 위치                                    |
| ------------ | ----------------------------------------------- |
| OCR          | Capture 마찰을 낮추는 수단                      |
| Contact 정보 | Person을 식별하고 연락하기 위한 일부 정보       |
| Graph UI     | 관계 기억을 탐색하는 인터페이스                 |
| 자연어 검색  | Recall을 수행하는 방식 중 하나                  |
| CRM 기능     | 필요한 경우 관계 행동을 돕는 주변 기능          |
| AI Agent     | 신뢰 가능한 Memory 위에서 작동할 장기 실행 계층 |

어느 하나도 단독으로 Persnapse의 정체성이 아니다. 차별화는 이들을 `Relationship → Context → Memory → Current Need → Action`으로 이어 주는 통합 구조에서 나온다.

## 10. 자료 간 권위와 확정도

### Canonical로 간주할 수 있는 내용

- Business Relationship Memory라는 제품 정의
- 관계 맥락 소실과 회상 실패라는 문제 정의
- Capture → Context → Memory → Recall → Action 루프
- Temporal Business Context Graph라는 개념적 중심
- 독립 Person Identity와 이름 기반 자동 병합 금지
- AI 제안과 사용자 확인의 역할 분리
- 사용자 확인 정보 우선과 Memory provenance
- Recall이 핵심 가치 발생 순간이라는 판단
- OCR, Graph, Search, Agent는 각각 계층 또는 수단이라는 경계
- 개인 관계 기억에서 시작해 관계 Intelligence로 확장하는 장기 방향

### 강하게 지지되지만 이후 확정이 필요한 내용

- Sales / BD를 최초 핵심 세그먼트로 선택
- 명함을 주요 초기 Capture 방식으로 선택
- Relationship Map과 자연어 Recall을 초기 경험에 포함
- Action을 Follow-up, 미팅 준비, 일정 등으로 구체화
- 개인에서 팀 관계 그래프로 확장

### 현재는 제안 또는 탐색 방향으로 유지할 내용

- 3D Graph Network를 기본 UI로 채택
- 밝은 UI와 한국어 중심이라는 구체 디자인 방향
- Free / Paid 기능 구분과 Freemium 사업 모델
- 특정 OCR 처리 계층과 모델 비용 전략
- “1주 안에” OCR 성능을 확보한다는 일정 가정
- P00~P05 문서 우선순위 체계를 공식 거버넌스로 채택

## 11. 현재 드러나는 핵심 긴장과 위험

### Capture가 제품을 잠식할 위험

명함 OCR은 데모가 쉽고 품질을 측정하기도 쉬워 개발의 중심이 되기 쉽다. 그러나 제품 가설은 Capture가 아니라 장기 Memory와 Recall에 있다. OCR 최적화가 Core Loop 검증을 늦추지 않도록 분리해서 판단해야 한다.

### Graph가 목적화될 위험

그래프는 시각적으로 강하지만 사용자가 실제 질문에 더 빨리 답하도록 하지 못하면 장식이 된다. Context Graph라는 데이터 개념과 2D/3D Graph UI 선택을 분리할 필요가 있다.

### 입력 마찰과 기억 품질의 상충

정확한 관계 맥락을 얻으려면 사용자 확인이 필요하지만 확인 단계가 많으면 지속적인 Capture가 어려워진다. 자동화 수준과 사용자 통제 사이의 균형이 중요한 제품 가설이다.

### 정확도와 유용성의 상충

보수적인 Identity 정책은 오류를 줄이지만 중복 Person과 불완전한 연결을 늘릴 수 있다. 반대로 공격적인 병합은 신뢰를 훼손한다. Persnapse가 어느 오류를 더 위험하게 보는지는 현재 자료상 명확하다. 잘못된 병합을 더 치명적으로 본다.

### Recall과 Action 사이의 정의 부족

Recall의 가치와 예시는 비교적 선명하지만, 어떤 Action까지 제품이 직접 책임질지는 덜 정해져 있다. 단순 제안, 리마인드 생성, 외부 도구 연동, 자동 실행은 서로 다른 제품 경계이므로 이후 구분이 필요하다.

### 개인과 팀 제품의 권한 차이

개인 관계 기억과 Team Relationship Graph는 데이터 소유권, 공개 범위와 관계 맥락의 민감성에서 크게 다르다. 장기 방향은 일관되지만 동일한 초기 제품으로 취급하면 안 된다.

## 12. 이후 제품 논의에서 확인해야 할 질문

다음 질문은 개발 명세가 아니라 제품 맥락의 빈틈을 확인하기 위한 것이다.

1. 첫 사용자가 Persnapse를 반복해서 여는 가장 구체적인 상황은 무엇인가?
2. 최초 검증할 Recall 질문 유형은 무엇인가?
3. “정확한 관계 맥락”을 사용자 관점에서 어떻게 판별하는가?
4. Capture 후 어느 정보까지 확인해야 Memory로 확정되는가?
5. 사용자가 직접 작성한 사실, AI 추론과 외부 출처 정보는 제품에서 어떻게 구분되어 보여야 하는가?
6. Action은 추천에서 끝나는가, 사용자의 승인 후 실행까지 포함하는가?
7. Relationship Map은 최초 가치 검증에 필수인가, 다른 Recall 인터페이스로도 가설을 검증할 수 있는가?
8. 사용자가 관계 정보를 맡길 수 있다고 느끼게 하는 프라이버시와 통제 경험은 무엇인가?
9. 명함이 없는 관계와 지속적인 Interaction은 어떤 방식으로 축적되는가?
10. 초기 사용자 세그먼트 안에서도 어떤 역할·업무 상황을 첫 웨지로 선택할 것인가?

## 13. 현재의 통합된 이해

Persnapse는 사용자가 아는 사람의 목록을 만드는 제품이 아니다. 사람과 함께 발생한 사건, 대화, 소개, 의도와 약속을 출처 및 시간성과 함께 기억하고, 현재 필요에 맞춰 신뢰할 수 있게 되살리는 제품이다.

제품의 핵심 자산은 연락처 데이터나 그래프 화면이 아니라 **사용자가 신뢰할 수 있는 관계 기억의 축적**이다. 제품의 핵심 순간은 그 기억이 적절한 사람과 이유를 찾아 주는 Recall이며, 장기 가치는 Recall이 실제 관계 행동으로 이어지고 다시 새로운 기억을 만드는 순환에서 발생한다.

이 이해를 훼손하지 않는 한 OCR, 자연어 입력, 음성, 그래프, 검색과 Agent는 교체하거나 단계적으로 도입할 수 있는 수단이다. 반대로 Identity, provenance, 시간성, 사용자 통제와 Core Loop는 Persnapse의 방향을 판단하는 상위 기준으로 유지해야 한다.
