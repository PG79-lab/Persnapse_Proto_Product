# 단일 명함 인식 1차 구현 로컬 검증 — 2026-10-11

> 2026-10-12 변경: 현재 프론트 작업·시험 주소는 `http://localhost:3000/#cards`다. 독립 페이지 코드는 제거했으며 아래 `/capture` 검증은 변경 전 실행 이력이다. 당시 별도 브라우저 스크립트의 “Integrated” 출력은 실제 `/capture`에서 API·DB·Storage를 함께 시험했다는 의미였고 통합 워크스페이스 화면의 전체 검증을 뜻하지 않았다.

## 테스트 경로

`npm run dev`를 실행한 뒤 `http://localhost:3000/capture`의 **명함 촬영** 탭을 연다. 현재 `.env.local`은 `BUSINESS_CARD_OCR_MODE=live`, `BUSINESS_CARD_OCR_PROVIDER=openai`, `AI_ROUTING_MODE=mock`으로 설정되어 있다. 사진을 올리면 실제 OpenAI OCR 호출과 비용이 발생한다. 비용 없이 화면만 시험할 때는 PowerShell에서 `$env:BUSINESS_CARD_OCR_MODE='mock'`을 설정한 뒤 서버를 시작한다. Mock 추출값은 이미지와 무관하다.

카메라 촬영 또는 파일 선택 → 추출 필드 수정 → **OK · 추출 정보 확정** → 자동 보정 미리보기 확인 또는 **명함 모서리 직접 지정** → 보정 이미지 저장 또는 기존 이미지 유지 → 새로고침 후 초안 재개 순서로 시험한다. 인물과 관계 기억은 뒤의 별도 저장 단계다. 시험 초안은 **이 명함 삭제**로 제거한다. 상세 동작과 파일 책임은 [card_recognition README](../../card_recognition/README.md)에 있다.

추가로 별도 mock OCR 서버에서 합성 명함을 브라우저로 업로드하고 실제 API·DB·Storage를 통해 필드 확정 → 평면 보정 저장 → 새로고침 재개 → 삭제까지 확인했다. 시험 초안도 정리했다.

전체 브라우저 검증의 첫 병렬 실행에서 녹음 파일 새로고침 테스트 1건이 실패했다. 같은 테스트의 단독 실행과 전체 1개 워커 재실행은 통과했다. 명함 E2E는 두 실행 모두 통과했다.

실제 촬영 명함 사진·정답 경로는 아직 제공되지 않았다. 따라서 사진별 OCR 정확도, 자동 코너 감지율, 원본 디자인 유사도, 모바일 p95 시간은 이번 검증 결과에 포함되지 않는다. 현재 시각 결과는 생성형 재구성이 아닌 원본 사진 기반 평면 보정이다.

## 통합 UI로 프론트 작업 대상 통일 검증 — 2026-10-12

기존 독립 화면·헤더·전용 컴포넌트 13개 파일을 삭제했다. `next.config.ts`에서 `/capture` → `/#cards`, `/people` → `/#people`, `/people/:personId` → 인물 ID를 가진 통합 프로필, `/recall?q=...` → 검색어를 채운 통합 어시스턴트로 307 이동한다. 검색은 사용자가 질문을 보내야 실행된다.

명함 UI는 `ContactGraph` → `CardImport` → `BusinessCardWorkspace`의 한 인스턴스로 연결한다. 어시스턴트에서도 같은 `/#cards` 페이지로 이동한다. 저장한 명함은 통합 프로필의 정보 탭에서 `CardViewer`로 이동·확대할 수 있다. 텍스트 기록 완료 후 프로필·검색 이동도 통합 UI의 콜백으로 처리한다. 검색 준비 복구 콜백을 고정해 상위 화면의 변경 때문에 준비 상태를 반복 조회하지 않도록 했다.

소스 참조에서도 독립 헤더·화면 import와 옛 페이지로 이동하는 UI 링크가 남아 있지 않음을 확인했다. 삭제 후 남은 빈 폴더는 실행·빌드에 포함되지 않는다. 빈 폴더 정리 명령은 자동 승인 검토에서 차단됐으며 상세 사유는 제공되지 않았다. 이번 변경은 로컬 작업 트리의 내용이며 새 Preview 배포는 수행하지 않았다.
