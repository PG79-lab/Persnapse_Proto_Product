# 명함 외곽·복원 개발 진행과 측정

2026-10-13 갱신: 실제 사진 27장 제공 이후 LC100을 선택했고, 사용자 승인에 따라
일반 `/#cards` 촬영 흐름에 LC100 → 원근 보정 → 2D 이미지 확인 → OCR을 연결했다.
[현재 통합 테스트 안내](card-pipeline-test-2026-10-13.md)를 우선 참고한다.
아래 단계별 표는 최초 개발 시점의 기록이며, 전체 v2 설계·모바일/품질 gate는 여전히 미완료다.

- 기준일: 2026-10-12, Asia/Seoul.
- 상태: **개발 진행 중. 1단계 준비 완료, 2단계 하위 검증 완료. 전체 설계 구현은 미완료.**
- 적용: 통합 `/#cards`. 실제 사진 경로는 제공될 때까지 보류한다.
- 기존 미커밋 변경: 작업 시작 시 75개 파일과 tracked binary diff를 Git 제외
  `output/card-rectification/baseline/`에 보존했다. 이후 비교에서 변경된 기존
  파일은 관련 작업 파일 8개이며 나머지 67개는 해시가 그대로다. 처음에 clean이던
  `tsconfig.json`에는 평가 출력 제외를 추가했다. reset·clean·commit은 하지 않았다.
- 외부 AI/OCR 호출: **0회**. E2E의 OCR·DB는 mock, ONNX·WASM은 실제 파일이다.

## 1단계 데이터와 대조 결과

도안 60개 × 촬영 변환 20개 = 정상 1,200장. 개발 36도안/720장, 튜닝
12도안/240장, 보류 12도안/240장이다. 부정 장면 300개와 비정상 입력
200개는 별도 보류 집합이다. 내용은 가상 이름·번호·`example.invalid` 주소다.
각 인쇄 영역의 glyph/logo 마스크와 polygon, 수학적 homography 정답을 둔다.

| 준비 지표                | 측정                                                    | 판정 |
| ------------------------ | ------------------------------------------------------- | ---- |
| 정상/부정/비정상 파일    | 1,200 / 300 / 200                                       | PASS |
| 이미지·마스크 SHA-256    | 6,500/6,500 일치                                        | PASS |
| 누락·중복 ID·분할 누출   | 각각 0건                                                | PASS |
| decode                   | 정상 포함 1,620개 성공, 의도한 형식/절단 오류 80개 거절 | PASS |
| 투영 좌표 잔차 최대      | 0.0000108243px, 준비 검증 상한 0.0001px                 | PASS |
| 전체 입력 처리 상태 기록 | 1,700/1,700; 별도 oracle 경로 1,200/1,200               | PASS |

manifest SHA-256:
`22ac661e2daf79c4596af4d4e7166968e5092ce614e73fe0ec27cac182ba141e`.
투영 잔차 상한은 float32 대응점으로 푼 OpenCV transform의 수치 오차 검증용이며,
설계의 좌표 왕복 상한 0.25px를 바꾼 것이 아니다.

다음은 **기존 알고리즘의 전체 합성 대조값**이다. 미검출도 성공률 분모와
IoU 집계에 포함한다. 코너 오차는 유한하고 대응 가능한 예측 851장만 계산하고
미검출 349장은 별도 표시한다.

| 지표                    | 기존 검출             | 정답 코너 입력 복원                 |
| ----------------------- | --------------------- | ----------------------------------- |
| 정상 외곽 성공          | 715/1,200 (59.58%)    | 1,200/1,200                         |
| 코너 Emean 평균 / p95   | 0.285764% / 1.354179% | 부동소수점 오차 수준                |
| Emax p95                | 1.587930%             | 부동소수점 오차 수준                |
| IoU 중앙값 / p5         | 0.997040 / 0          | 1 / 약 1                            |
| 정상 후보의 내용 잘림   | 1건                   | 0건                                 |
| 부정 장면의 복원 후보   | 123/300               | 해당 경로 없음                      |
| 비정상 입력의 복원 후보 | 40/200                | 해당 경로 없음                      |
| 기존 검출기 품질        | **FAIL**              | 검출 정확도 시험이 아닌 oracle 대조 |

기존 비정상 40건은 교차 수동점을 재정렬해 복원한 경로다. UI에서는 이번에
적용을 차단했지만 기존 저수준 복원 API 자체의 재정렬 변경은 3단계에 남겼다.
형식 오류 80건은 기존 경로의 error 결과로 원자료에 보존했다.

합성 보류 240장의 oracle 복원 영상은 동일 촬영 소스·동일 출력 크기·고정
보간·JPEG/decoder로 비교했다. 임의 resize, 추가 homography, 평행 이동은 없다.

| 영상 지표            | 최악 측정값      | 기준   | 결과                |
| -------------------- | ---------------- | ------ | ------------------- |
| 전체 SSIM            | 0.996449         | ≥0.990 | 240/240 PASS        |
| 전체 PSNR            | 47.553590dB      | ≥38dB  | 240/240 PASS        |
| 글자·로고 영역 SSIM  | 0.995427         | ≥0.980 | 모든 지정 영역 PASS |
| 동일 영상 계산 정답  | SSIM 1, PSNR +∞  | 동일   | PASS                |
| 픽셀 1단계 차이 정답 | PSNR 48.130804dB | 동일   | PASS                |

oracle 경로도 기존의 **estimated 비율**을 유지하므로 실제 비율 복원 통과가
아니다. 실측 비율·ΔE00·재저장 소스 품질은 NOT_RUN이다. 실제 채택률도 미측정이다.

기존 대조 호출의 p50/p95/p99는 52.1/180.5/450.9ms, oracle 호출은
36.5/62.4/81.2ms였다. 이는 **로컬 fetch·직렬화 포함, 20장마다 새 페이지,
성공/실패 섞인 정확성 대조 실행**이다. warm 200회·cold 50회, 통제 네트워크,
2/8/12MP, UI·OCR 또는 모바일 성능 gate의 수치로 사용하지 않는다.
관리 버퍼·heap·미해제 객체 수는 NOT_RUN이며 0으로 보고하지 않는다.

## 2단계 실제 모델 하위 검증

기준 PC: Samsung 750XDA, i3-1115G4, RAM 8,299,986,944 bytes, Windows 11
Home 10.0.26200. Chrome 155.0.8059.39. 모바일 viewport로 대체하지 않았다.
라이브러리는 `onnxruntime-web`·`onnxruntime-node` 1.30.0, OpenCV.js
5.0.0-release.1이다. 동일 버전 MJS·WASM을 동일 출처에서 로드한다.

| 모델       | 실제 파일 bytes | SHA-256                                                            |
| ---------- | --------------: | ------------------------------------------------------------------ |
| LC100      |       4,767,987 | `f4117b786e3a18470f3865c93f3c2bd69d9b998edd60f385574a5c665e79594e` |
| FastViT-T8 |      13,167,814 | `950070fd4a46e25d46db7c35d0ed77612d9063f70d4543c7c504f0da6a943a89` |

원 저장소 commit은 `3275b0f07f8e99d8c01cb0774dea2549be1416b6`이다. ONNX
checker 검사와 입출력 metadata를 저장했다. batch 1 실행의 heatmap 크기는
`[1,4,128,128]`이었다. 원 ONNX의 symbolic 차원도 manifest에 별도로 남겼다.

| 하위 검사                            | 측정                                          | 판정                                           |
| ------------------------------------ | --------------------------------------------- | ---------------------------------------------- |
| CPU vs single-thread WASM            | 모델별 30개, 전체 3,932,160 원소              | 허용 오차 초과 0, NaN/Inf 0; PASS              |

| production 실제 모델 실행            | T8 20/20, LC100 20/20                         | 자산 누락·실행 오류 0; PC PASS                 |

전처리는 pinned DocAligner/Capybara의 bilinear BGR 입력 계약을 재현했다.
후처리는 0.3 threshold, 원 크기 확대, uint8, Otsu, 외부 윤곽·최대 면적·중심점
순서다. 실제 모델 출력의 공식 코너 30개 비교는 아직 하지 않았다. 이
어댑터는 명함 존재 판정기가 아니며 높은 model response만으로 후보를 채택하지 않는다.

Worker에 DOM 없이 typed array로 OpenCV Mat을 만들고 finally에서 Mat/tensor를
해제하는 경로를 추가했다. 전체 자원 계수 100회 검증은 미측정이다. 제품 자동
복원은 기존 경로이며 새 모델을 자동 채택하거나 기본 전환하지 않았다.

## 통합·검증과 원자료

- `/#cards`의 수동 편집과 복원은 세션 촬영 파일을 우선한다. 새로고침 이후에는
  기존 저장 원본을 사용한다. restoration_source 저장 계약은 미구현이다.
- 작업 교체·거절·삭제·unmount 시 revision 소유를 무효화한다. 늦은 응답
  소유 검사 200회 단위 테스트에서 적용 0건이다. 브라우저 응답 순서 주입
  200회 gate를 대체하지 않는다. 기존 메인 스레드 WASM은 즉시 중단하지 않는다.
- 촬영/미리보기/복원 Object URL을 추적하고 교체·삭제·unmount에서 해제한다.
- 필드 OK와 이미지 채택, 인물·만남 저장의 기존 별도 동작은 유지한다.
- 기본 `npm run verify` 통과. 이후 Worker 수명주기 검사를 포함한 최종 단위
  테스트는 **46개 파일·256개 테스트 통과**다. Windows 자원 부족을 겪어 Vitest 최대 Worker를
  4개로 제한했다. 기존 lint 경고 2개는 그대로이며 오류는 0개다.
- 통합 E2E 3개 통과. OCR/DB는 mock, 모델 실행은 실제 파일이다.
- `git diff --check` 통과. 실제 DB/Storage writes·외부 AI 호출은 하지 않았다.

초기 실행의 자원 부족 실패는 `output/card-rectification/attempts/`에 보존했다.
최종 실행에서 빠른 결과만 추려 사용하지 않았다. PC 자원 조건이 통제된
성능 시험이 아니므로 최초 실패가 없었던 것처럼 성능 PASS를 주장하지 않는다.

원자료 경로(모두 Git 제외):

- `output/card-rectification/phase1/measurements.jsonl`, `report.json`, `conditions.csv`,
  `report.html`, `image-metrics.jsonl`, 원본/결과/기준 JPEG와 해시.
- `output/card-rectification/phase2/measurements.jsonl`, `adapter-measurements.json`,
  `provenance.json`, `summary.json`, 고정 입력/CPU 기준 f32와 SHA-256.
- `test-results/playwright/.../model-production.json`, 실제 production 40회 결과.
- `output/card-rectification/verify.log`, `e2e.log`, `final-unit.log`.

조건별 분모·실패, 최악 품질 10개와 가장 느린 10개는 HTML/JSON 보고서에 있다.
카드 bootstrap·최종 채택률 신뢰구간은 후보/실제 카드 비교 미실행으로 NOT_RUN이다.
합성 부정 장면을 실제 오검출 확률 표본으로 사용하지 않는다.

다음 개발 순서는 2단계의 실제 모델 후처리와 DocQuad 계약, 3단계 좌표·ROI·비율·
복원기, 4단계 전체 UI 준비 흐름, 5단계 v2 저장이다. 실제 사진을 기다려야 하는
작업과 기술 구현 미완료를 구분하며, 기술 구현이 사진 때문에 막혔다고 기록하지 않는다.
