# LC100 20분 개선·회전 탐색 결과

2026-10-13. 사용자 승인한 20분 작업 범위의 소규모 결과다. 기존 명함 기준 커밋은 `88480f2`; 이번 변경은 미커밋이며 관련 없는 작업 트리를 보존했다.

## 구현

- 후처리 루프에서 OpenCV typed-array getter를 픽셀마다 호출하지 않고 한 번 가져와 재사용한다. threshold·해상도·contour·centroid 정책은 유지한다.
- `/#cards`의 보정 이미지 확인 단계에 **오른쪽으로 90도 회전** 버튼을 연결했다. 90/180/270도 실제 JPEG를 생성하고 표시·다운로드·OCR에 전달한다. 반복 회전은 기준 보정본에서 생성하며 0도에서는 기준 파일을 재사용한다.
- 원본 파일·모서리 좌표는 유지한다. 회전 중 OCR/수동 보정은 비활성화하고, 취소·삭제·unmount의 늦은 결과를 revision/AbortSignal로 막는다. 실패 시 이전 보정본을 유지한다.
- 비스듬한 촬영은 기존 원근 보정, 자동 실패는 수동 모서리 편집으로 처리한다. 자동 글자 방향 판정·Worker 재사용·실측 비율 복원은 이번에 구현하지 않았다.

### 실제 OCR

기존 3002 서버/서비스·비용 정책을 사용해 001의 보정 전/후 **2회** 요청했다. 두 요청 모두 HTTP 201/OpenAI, 약 **5,318ms / 3,746ms**. 최종 명함/Identity 저장은 하지 않았고 이번 두 draft만 삭제했다(각 HTTP 204). 비용 원장은 유지한다.

영문 이름·이메일·전화는 두 응답이 같고 회사 해석은 달랐다. 초기 정답이 한글 이름만 허용해 명함의 영문 이름 응답을 엄격 불일치로 계산했고, 전화 전사에도 재검수가 필요하다. 따라서 저장된 scores는 잠정 진단값이며 **OCR 정확도 합격/불합격 판정은 보류**한다. 두 호출의 지연 차이를 일반 성능 개선으로 주장하지 않는다. 표본 1장이며 전체 CER·27장 OCR 평가는 미실행이다.
