# Card recognition

단일 명함의 촬영 후 시각 복원과 보기 전용 표시를 담당한다. 기존 OCR 제공자, 비용 예약, 비공개 Storage, 관계 기억 commit은 `src/server` 경로를 재사용한다.

현재 통합 촬영 흐름은 촬영/업로드 → LC100 Worker 감지 → OpenCV 원근 보정 → 2D 이미지 확인 → 기존 OCR이다. 상세 실행 방법은 [통합 파이프라인 테스트](../docs/operations/card-pipeline-test-2026-10-13.md)를 따른다. 모델 로드·검출 실패는 OCR 전 수동 네 점 보정으로 이어진다. 초기 설계의 전용 복원 소스·v2 저장 계약·경계 정밀화·실측 비율·모바일 최종 검증은 후속 작업이다.

단계별 완료·품질·시간·메모리·저장 안정성은 [정량 벤치마크 기준](../docs/plans/card-boundary-rectification-benchmark-2026-10-12.md)으로 판정한다. 미측정·표본 부족은 통과와 구분한다.

| 파일                                 | 역할                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `restore-image.ts`                   | OpenCV 원근 변환·JPEG 생성. LC100/수동 코너를 받으며 기존 자동 검출 호출도 지원한다. |
| `card-corner-editor.tsx`             | 자동 감지가 틀리거나 실패하면 사용자가 네 모서리를 지정한다.                         |
| `card-viewer.tsx`                    | 보기 전용 카드 이미지, 원본 전환, 이동, 확대를 제공한다.                             |
| `geometry.ts`                        | 꼭짓점 순서와 출력 크기 계산.                                                        |
| `contracts.ts`, `jpeg-dimensions.ts` | 확인/복원 API 입력 및 이미지 크기 검증.                                              |
| `contact-numbers.ts`                 | 명함 표기로 전화·휴대폰·팩스·미분류를 구분하고 원문 표기를 보존한다.                 |
| `contact-number-fields.tsx`          | 번호 종류별 확인·수정과 OK 결과·인맥 프로필의 번호 표시.                             |

번호 분류의 저장·호환·검증 규칙은 [명함 연락처 번호 종류 보존](../docs/decisions/0020-business-card-contact-number-types.md)을 따른다. 별도 LLM 호출 없이 기존 추출 요청에서 종류와 원문 표기를 보존한다. 종류 정보가 없는 과거 명함은 미분류로 표시하며, 새 명함 확인 화면에서 수동 분류할 수 있다.

`npm run dev`와 `npm run build` 전에 npm 스크립트가 OpenCV·ONNX Runtime·로컬 모델·합성 시험 자산을 public에 복사한다. 모델은 `npm run card:download-models`로 별도 준비한다. 생성 바이너리는 Git에서 제외하며 모델 manifest와 라이선스를 추적한다. 브라우저는 OCR 전 이미지 처리 단계에서 자산을 사용한다.

현재 디지털 명함은 **원본 사진 기반의 평면 보정 이미지**다. 디자인을 새로 그리거나 글자·로고를 생성하지 않는다. 자동 보정 결과는 사용자 확인 후 새 비공개 Storage 경로에 저장하며, 원본 사진은 유지한다. 실제 명함 사진과 정답이 제공되면 OCR 정확도, 코너 오류, 원본 유사도, 모바일 지연을 측정해 더 강한 복원 후보를 결정한다.

## 로컬에서 직접 시험하기

1. `npm run dev`를 실행하고 `http://localhost:3000/#cards`에서 통합 워크스페이스의 **명함 등록** 화면을 연다. 카메라·파일 입력·필드 확인·복원·관계 기억 저장은 이 화면에서 이어진다.
2. 카메라로 명함 한 장을 촬영하거나 **이미지 업로드**로 사진 한 장을 선택한다. 현재 로컬 `.env.local`은 명함 OCR을 `live`/OpenAI로 설정했으므로 실제 API 호출과 비용이 발생한다. 비용 없는 화면 시험은 서버 시작 전에 `BUSINESS_CARD_OCR_MODE=mock`으로 실행한다. Mock 추출값은 사진 내용과 일치하지 않는다.
3. 검출 테두리와 2D 이미지를 확인한다. 필요하면 **OCR 전 모서리 직접 지정**으로 보정한다. **이 2D 이미지로 OCR 실행** 후 정보를 확인·수정하고 **OK · 추출 정보 확정**을 누른다. 원본과 채택한 보정본을 별도로 유지한다.
4. 페이지를 새로고침해 확인한 명함과 관계 맥락 입력 화면이 다시 나타나는지 본다. 관계 기억을 시험할 때만 맥락과 인물을 별도로 저장한다. 시험 초안은 **이 명함 삭제**로 제거할 수 있다.

자동 브라우저 검증은 `tests/e2e/capture.spec.ts`의 명함 테스트에서 통합 UI의 업로드, 필드 확정, 수동 평면 보정, 저장 및 재개, 인맥 프로필과 어시스턴트 이동을 확인한다. DB·Storage 검증은 `npm run db:verify:phase5`(mock) 또는 `npm run db:verify:phase5:live`(유료 OCR)로 실행하며 생성한 합성 데이터를 정리한다. 새로운 DB 환경에서는 `supabase/migrations/20261011100000_business_card_fields_confirmation.sql` 적용이 먼저 필요하다.
